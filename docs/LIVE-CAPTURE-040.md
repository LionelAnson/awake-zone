# 0.4.0：将采集磨砂接入个人时钟

日期：2026-09-30。当前仅验证本机 Windows 26200 x64；macOS 保留工程结构，未运行验证。

## 最终设计

- Windows 独立/置顶时钟：WGC 显示器采集，会话内排除时钟自身，GPU 裁剪局部区域并做 sigma=6 的高斯模糊，通过 DirectComposition 放在透明 WebView 文字下方。
- FrameArrived 唤醒独立绘制线程，丢弃积压旧帧，交换链最多排队一帧。没有新增前端组件库、独立 UI 框架或 Windows App SDK Runtime。
- 返回桌面：先停止采集并释放合成对象，再使用原有壁纸取样。隐藏窗口关闭采集会话，恢复显示时重建。退出释放 worker、会话和合成对象。
- 按用户本轮追加要求，统一叠加 `#d8d8d8 / 10%` 浅灰色层，文字和按钮位于其上。没有恢复日间/夜间模式。
- 深背景白字，灰/亮背景黑字。字色仍依据背景取样亮度和原有滞回阈值；不把浅灰层当作系统主题。
- Ctrl+Shift+Win+Z 保持置顶/回到桌面的含义；隐藏后优先唤到前台，包括隐藏前已经置顶的情况。没有未经确认增加第二组快捷键。
- 保留提前注册 LocalState 的修正，并增加 `startup_ready`：前端异步等待完整 setup 完成再读取设置，避免 WebView 更早加载时误报状态未注册。

实现：`src-tauri/native/live_glass.cpp`、`src-tauri/src/live_glass.rs`、`src-tauri/src/backdrop.rs`、`src-tauri/src/lib.rs`、`src/main.ts`、`src/style.css`。C++ 静态链接，桥接只传 HWND、错误、亮度和计数，不通过 IPC 传图。

## 数据与系统影响

置顶状态会在内存中取得显示器画面，但只裁剪绘制时钟下方区域；不保存、不上传真实应用画面。每半秒临时读回亮度用于字色判断。保留系统采集指示；没有设置全局 WDA 排除，所以不会主动让时钟在所有截图/远程工具中消失。

需要运行时支持会话内排除 API。缺失接口会提示；启动失败时退回桌面方案。其他 Windows 版本、HDR、跨显示器窗口、实际拔屏、实际休眠、远程端显示和长期能耗尚未验证。

## 未通过尝试与保留的限制

- 最初启动采样偶发出现 `state not managed`，错误文字把卡片撑大并污染测量。该轮图像和失败分析保留；新增就绪握手后重新验证，不把它算作材质失败或通过。
- 发现 Win32 外框和客户区存在尺寸差异后，曾尝试移除框架样式；回归发现桌面往返横向偏移 18 px，因此撤回这项改动。它没有替换正在运行的安装版。外框坐标与内容区域不同本身不能证明可见边框；正式代码保留已通过实际图像与锚点回归的路径。
- 托盘图标/菜单的 UI Automation 自动点击未稳定成功，不能标成鼠标托盘操作已验证。菜单命令共用的显示、隐藏、设置、模式切换在原生测试中验证；实际托盘点击仍需人工检查。
- 没有实测登录/重启；验证了真实自启项和路径保留。没有把旧版本的登录或托盘结果复用为本轮通过。
- 小方块的约 48 FPS 是此前独立实验的数据，不直接宣称时钟也具有相同物理端到端延迟；最终时钟的主观延迟需要用户观察。

## 回退与交付

安装版更新前备份原 EXE 至 `release/rollback-*`，不回写旧设置。真实设置文件是 EFS 加密文件，跨盘 Copy-Item 备份曾失败；随后以显式字节读取保存副本并核验真实文件未改变。更新、测试后均检查作息、桌面锚点和自启，避免用旧备份覆盖用户期间的调整。

NSIS 打包时会把 EXE 中 `BUNDLE_TYPE_VAR_UNK` 改为 `BUNDLE_TYPE_VAR_NSS`，因此安装 EXE 与构建目录原 EXE 的 SHA-256 不同。首次核对差异仅这 3 个字节；最终安装亦独立记录哈希和版本。

开发与构建入口见 README；正式构建脚本为 `scripts/build-live-release.mjs`，隔离构建为 `scripts/build-hotkey-probe.mjs`。两者均保存配置/源码快照并沿用独立构建目录。`native/generated` 的固定 WinRT 投影来源见 `native/README.md`，本轮没有升级主依赖。
